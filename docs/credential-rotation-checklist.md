# 生产凭据轮换清单

本清单只记录“凭据类别、负责人角色、轮换日期和验证结果”，不得填写真实秘密。

## 立即轮换

- QQ Connect App Key：在 QQ 互联后台生成新值，先更新生产秘密配置并完成真实登录，
  再撤销旧值；确认 URL、应用日志、Caddy 日志和 Git 均无新旧密钥。
- 旧 QQ 邮箱 SMTP 授权码：域名邮箱投递通过后停用旧码，生产切换为
  `no-reply@sekai-tools.cn` 的独立 SMTP 凭据。
- 任何曾进入聊天、截图、终端历史、工单或公开日志的 Token/Secret：一律视为已泄露，
  先撤销再替换，不以删除聊天或 Git commit 代替轮换。

## 新建后验证

- COS CAM SecretId/SecretKey：最小前缀权限、无删除/改 ACL/跨桶权限，完成上传、HEAD
  和随机取回后记录验证日期。
- `age` identity：生产仅有 public recipient；私钥离线双份保存，执行一次完整解密与
  临时数据库恢复后封存。
- SMTP：使用独立应用授权码，验证 SPF/DKIM/DMARC；不得复用邮箱网页登录密码。
- 数据库、JWT、OAuth/Webhook、Android 签名、SSH：逐项确认生产与开发隔离、文件
  权限、撤销能力、负责人和下次轮换日期。

## 每次轮换流程

1. 创建新凭据并缩到最小权限，不立即删除旧值。
2. 只通过秘密管理渠道更新服务器；备份原配置的加密副本。
3. reload/重建最小范围服务，执行登录、邮件、归档或备份专项 smoke。
4. 检查仓库、构建产物、URL、访问日志和应用日志没有秘密。
5. 撤销旧凭据，验证旧值确实失败且新值正常。
6. 记录类别、日期、执行/复核角色、验证结果和下次轮换日期，不记录秘密本身。
